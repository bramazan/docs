Payven hata yanıtları [RFC 9457 — Problem Details for HTTP APIs](https://www.rfc-editor.org/rfc/rfc9457) standardına uyar. Tüm hata response'larının body'leri `application/problem+json` MIME tipindedir; HTTP durum kodu kategoriyi, gövdedeki `code` alanı ise hatanın programatik tipini belirtir.

## Hata yanıt formatı

```http
HTTP/1.1 422 Unprocessable Entity
Content-Type: application/problem+json
X-Correlation-Id: 9f1c8e76-2a3b-4f12-9c8d-12cb24a8a8a8
```

```json
{
  "type":           "https://docs.payven.com.tr/errors/REFUND_AMOUNT_EXCEEDS_REMAINING",
  "title":          "İade tutarı kalan tutarı aşıyor",
  "status":         422,
  "code":           "REFUND_AMOUNT_EXCEEDS_REMAINING",
  "detail":         "İade tutarı kalan tutarı (15000 kuruş) aşamaz.",
  "instance":      "/api/v1/payments/8e3f5c12-.../refund",
  "correlation_id": "9f1c8e76-2a3b-4f12-9c8d-12cb24a8a8a8"
}
```

| Alan | Zorunluluk | Açıklama |
|---|---|---|
| `type` | Zorunlu | Hata tipinin kanonik URI'si. Aynı zamanda dokümantasyon linki olarak çalışır. |
| `title` | Zorunlu | Kısa, insan-okur başlık (Türkçe). |
| `status` | Zorunlu | HTTP status kodu (header ile aynı değer, gövdede yinelenir). |
| `code` | Zorunlu | Programatik hata kodu. `type` URI'sinin son segmenti. **İki format vardır:** altyapı kodları `lowercase_snake_case` (`validation_failed`), ürün/iş kuralı kodları `PV_BÜYÜK_HARF` (`PV_BANK_DECLINED`) — bkz. [Kod formatları](#kod-formatlari). |
| `detail` | Opsiyonel | Bu özel duruma ilişkin açıklayıcı mesaj. |
| `instance` | Opsiyonel | Hatanın oluştuğu kaynak yolu. |
| `correlation_id` | Opsiyonel | İstek zinciri kimliği. Response header'ı `X-Correlation-Id` ile aynı. Destek talebinde paylaşın. |

## HTTP kategorileri

| HTTP | Kategori | Örnek `code` | Retry |
|---|---|---|---|
| `400` Bad Request | Geçersiz gövde, eksik alan, format hatası | `bad_request`, `merchant_context_missing` | Düzeltmeden tekrarlamayın |
| `401` Unauthorized | Token yok, geçersiz, expire | `unauthorized`, `client_unauthorized`, `refresh_token_expired` | Yeniden token alın |
| `403` Forbidden | Yetki yok, modül kapalı | `forbidden`, `feature_not_available` | Hayır — yetki/lisans çözülmeden tekrar göndermeyin |
| `404` Not Found | Kaynak bulunamadı | `resource_not_found` | Hayır |
| `409` Conflict | Idempotency çakışması, durum geçişi geçersiz | `conflict`, `idempotency_key_in_use`, `invalid_state` | Hayır |
| `422` Unprocessable Entity | İş kuralı veya validasyon ihlali | `validation_failed`, `PV_BANK_DECLINED`, `PV_CANNOT_REFUND` | Hayır — istek/iş kuralı düzeltilmeden retry yapmayın |
| `429` Too Many Requests | Rate limit aşıldı (`Retry-After` header gönderilir) | `rate_limit_exceeded` | Backoff |
| `500/502/503` | Sunucu / bağlantı hatası | `internal_server_error`, `bad_gateway`, `service_unavailable` | Backoff |
| Network timeout | Ağ veya gateway timeout | — | Idempotency-Key ile |

<Note>
**Banka reddi de bir hata yanıtıdır.** Gateway'e ulaşmış ama banka tarafında reddedilen
ödeme `422 Unprocessable Entity` + `application/problem+json` ile döner; gövdede
`code: "PV_BANK_DECLINED"` ve banka ham yanıt kodu (`provider_error_code`, örn. `"51"` —
yetersiz bakiye) yer alır. Sonuç değerlendirmesini yalnız HTTP durum kodu üzerinden
yapın.
</Note>

## Kod formatları

`code` alanı iki ayrı kümeden gelir. **Kodlarınızı yazarken bu ayrımı gözetin** — ürün hatalarını
snake_case değerlerle karşılaştırırsanız hiçbir koşul eşleşmez.

| Küme | Format | Kim üretir | Tam liste |
|---|---|---|---|
| **Altyapı kodları** | `lowercase_snake_case` | Ortak API katmanı (auth, validasyon, rate limit, idempotency) | Aşağıdaki tablolar |
| **Ürün / iş kuralı kodları** | `PV_BÜYÜK_HARF` | İlgili ürün (Sanal POS, Para Transferi…) | [Sanal POS → Payven Domain Kodları](/sanal-pos/errors/payven-codes) (107 kod) |
| **Banka kodları** | Bankaya göre değişir | İşlemi yürüten banka; `provider_error_code` alanında döner — `code` alanında **değil** | [Banka Yanıt Kodları](/sanal-pos/errors/bank-codes) |

<Warning>
Ödeme reddi, iade kuralı, 3D Secure gibi **iş kuralı hataları `PV_` öneklidir**
(`PV_BANK_DECLINED`, `PV_CANNOT_REFUND`, `PV_3DS_FAILED`). Bu sayfadaki snake_case tablolar
yalnızca **altyapı** hatalarını kapsar.
</Warning>

## Yaygın hata kodları

### Kimlik doğrulama / yetki

| `code` | HTTP | Anlam |
|---|---|---|
| `unauthorized` | 401 | Token yok, geçersiz, süresi dolmuş veya imza doğrulanamadı |
| `client_unauthorized` | 401 | `/token` veya `/refresh`: API anahtarı geçersiz, pasif ya da silinmiş — **retry etmeyin** |
| `refresh_token_expired` | 401 | `/refresh`: oturum sona erdi (boşta kalma ya da 10 saatlik mutlak sınır). **Beklenen** — `client_credentials` ile yeniden token alın |
| `refresh_token_invalid` | 401 | `/refresh`: token bozuk, başka realm'e ait veya iptal edilmiş |
| `audience_invalid` | 401 | Token başka bir ürün için üretilmiş (API anahtarının scope'unda bu ürün yok) |
| `forbidden` | 403 | Bu rol/anahtar bu kaynağı göremez |
| `feature_not_available` | 403 | Modül bu tenant için etkin değil |
| `merchant_context_missing` | 400 | Mutasyon isteğinde `X-Merchant-Id` / `X-External-Merchant-Id` yok |

<Note>
Bayi çözümleme hataları (geçersiz/pasif bayi) ürün kodu olarak döner:
`PV_INVALID_MERCHANT_ID`, `PV_MERCHANT_NOT_FOUND`, `PV_MERCHANT_INACTIVE`.
</Note>

### İstek formatı / validasyon

| `code` | HTTP | Anlam |
|---|---|---|
| `bad_request` | 400 | Genel istek hatası — gövde okunamadı, alan tipi hatalı |
| `validation_failed` | 422 | Validasyon kuralı ihlali — `errors[]` ile alan listesi |
| `unsupported_media_type` | 415 | `Content-Type` `application/json` değil |
| `method_not_allowed` | 405 | HTTP metodu bu yol için tanımlı değil |
| `not_acceptable` | 406 | `Accept` header'ı desteklenmiyor |

<Note>
Alan-bazlı iş kuralı hataları (tutar, kart, IBAN, taksit) ürün kodu olarak döner:
`PV_INVALID_AMOUNT`, `PV_INVALID_CARD`, `PV_CARD_EXPIRED`, `PV_INVALID_INSTALLMENT`,
`PV_INVALID_CURRENCY` — tam liste [Payven Domain Kodları](/sanal-pos/errors/payven-codes).
</Note>

Validasyon hatalarında alan-bazlı detay `errors[]` array'inde döner:

```json
{
  "type":   "https://docs.payven.com.tr/errors/validation_failed",
  "title":  "Validasyon hatası",
  "status": 422,
  "code":   "validation_failed",
  "detail": "1 alan geçersiz",
  "errors": [
    {
      "field":   "amount.amount",
      "code":    "below_minimum",
      "message": "Tutar 100 kuruşun altında olamaz."
    }
  ]
}
```

### Kaynak / durum

| `code` | HTTP | Anlam |
|---|---|---|
| `resource_not_found` | 404 | Kaynak bulunamadı |
| `conflict` | 409 | Genel çakışma |
| `invalid_state` | 409 | Kaynak bu işlem için uygun durumda değil |

### Ödeme, iade, 3D Secure ve banka hataları

Bu hatalar **ürün kodu** olarak döner (`PV_` önekli) — bu sayfadaki snake_case tablolarda **yer almazlar**.
Sık karşılaşılanlar:

| `code` | HTTP | Anlam |
|---|---|---|
| `PV_BANK_DECLINED` | 422 | Banka işlemi reddetti — banka ham kodu `provider_error_code` alanında |
| `PV_INSUFFICIENT_FUNDS` | 422 | Bakiye yetersiz |
| `PV_CARD_EXPIRED` | 422 | Kartın son kullanma tarihi geçmiş |
| `PV_DO_NOT_HONOR` | 422 | Banka işleme izin vermedi |
| `PV_3DS_FAILED` | 422 | 3D Secure doğrulaması başarısız |
| `PV_FRAUD_SUSPECTED` | 422 | İşlem güvenlik nedeniyle reddedildi |
| `PV_CANNOT_REFUND` | 422 | Mevcut durumda iade yapılamaz |
| `PV_TIMEOUT` | 504 | İşlem zaman aşımına uğradı |

**Tam liste (107 kod):** [Sanal POS → Payven Domain Kodları](/sanal-pos/errors/payven-codes).
Banka ham kodları: [Banka Yanıt Kodları](/sanal-pos/errors/bank-codes).

### Idempotency / rate limit

| `code` | HTTP | Anlam |
|---|---|---|
| `idempotency_key_in_use` | 409 | Aynı `Idempotency-Key` farklı body için kullanılmış |
| `rate_limit_exceeded` | 429 | İstek limiti aşıldı (`Retry-After` header'ına uyun) |

Banka yanıt kodlarının ve konnektör hata mesajlarının tam listesi: [Sanal POS → Hata Kodları](/sanal-pos/errors/overview).

## Retry stratejisi

Sadece **geçici hatalar** için retry uygun: `429`, `5xx`, network timeout. **Idempotent olmayan** işlemleri retry ederken mutlaka aynı `Idempotency-Key` kullanın — yoksa aynı işlem birden fazla yapılır.

Önerilen pattern: **exponential backoff + jitter**.

```
1. deneme: hemen
2. deneme: ~1 sn sonra
3. deneme: ~2 sn sonra
4. deneme: ~4 sn sonra
5. deneme: ~8 sn sonra (üst limit)
```

<CodeGroup>
```csharp C#
async Task<HttpResponseMessage> SendWithRetryAsync(
    Func<HttpRequestMessage> requestFactory,
    int maxAttempts = 5,
    CancellationToken ct = default)
{
    var rng = new Random();
    for (int attempt = 0; ; attempt++)
    {
        var response = await _http.SendAsync(requestFactory(), ct);
        if (response.IsSuccessStatusCode) return response;

        var status = (int)response.StatusCode;
        var retryable = status == 429 || status >= 500;
        if (!retryable || attempt >= maxAttempts - 1) return response;

        var delaySec = Math.Pow(2, attempt);
        if (response.Headers.RetryAfter?.Delta is { } ra) delaySec = ra.TotalSeconds;
        var jitter = rng.NextDouble() * 0.5;
        await Task.Delay(TimeSpan.FromSeconds(delaySec + jitter), ct);
    }
}
```

```javascript Node.js
async function retry(makeRequest, { maxAttempts = 5 } = {}) {
  for (let attempt = 0; ; attempt++) {
    const res = await makeRequest();
    if (res.ok) return res;

    const retryable = res.status === 429 || res.status >= 500;
    if (!retryable || attempt >= maxAttempts - 1) return res;

    const retryAfter = Number(res.headers.get("retry-after"));
    const baseSec = Number.isFinite(retryAfter) ? retryAfter : 2 ** attempt;
    const jitter = Math.random() * 0.5;
    await new Promise((r) => setTimeout(r, (baseSec + jitter) * 1000));
  }
}
```

```python Python
import asyncio, random

async def retry(make_request, max_attempts: int = 5):
    for attempt in range(max_attempts):
        res = await make_request()
        if 200 <= res.status_code < 300:
            return res

        retryable = res.status_code == 429 or res.status_code >= 500
        if not retryable or attempt == max_attempts - 1:
            return res

        retry_after = res.headers.get("retry-after")
        base = float(retry_after) if retry_after else 2 ** attempt
        await asyncio.sleep(base + random.random() * 0.5)
```
</CodeGroup>

<Tip>
Tekrar denerken **aynı `Idempotency-Key`** ile gönderin. Aynı işlemin iki kez
oluşmasını engeller. Bkz. [Idempotency](/documentation/concepts/idempotency).
</Tip>

## Müşteriye gösterme

`detail` alanı son kullanıcıya gösterilebilir nitelikte yazılır. Yine de hassas durumlarda (fraud, fraud-review, banka tarafı reddi) genel bir mesajla geçiştirmek daha güvenlidir:

```javascript
function userMessage(problem) {
  switch (problem.code) {
    case "validation_failed":
      return problem.detail;
    // Ürün kodları PV_ öneklidir — snake_case ile karşılaştırmayın.
    case "PV_BANK_DECLINED":
    case "PV_DO_NOT_HONOR":
    case "PV_INSUFFICIENT_FUNDS":
    case "PV_FRAUD_SUSPECTED":
      return "İşleminiz onaylanmadı. Farklı bir kart deneyebilirsiniz.";
    case "rate_limit_exceeded":
      return "Şu an çok fazla istek alıyoruz. Lütfen kısa bir süre sonra tekrar deneyin.";
    default:
      return "İşleminiz gerçekleştirilemedi. Lütfen tekrar deneyin.";
  }
}
```

## Destek talebi açarken

Her hata yanıtında dönen **`correlation_id`** değerini paylaşın — log zincirini saniyeler içinde bulabiliriz. Response header'ındaki `X-Correlation-Id` ile gövdedeki `correlation_id` aynı değerdir.

```text
Konu:   Refund 422 — REFUND_AMOUNT_EXCEEDS_REMAINING
Detay:  correlation_id: 9f1c8e76-2a3b-4f12-9c8d-12cb24a8a8a8
        instance:      /api/v1/payments/8e3f5c12-.../refund
        zaman:         2026-05-05T14:23:11+03:00
```
