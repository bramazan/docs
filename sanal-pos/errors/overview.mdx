Sanal POS hata kodları **üç kategoriye** ayrılır ve **formatları farklıdır** — kod yazarken bu ayrım önemlidir:

| Kategori | Format | Kaynak | Örnek değerler |
|---|---|---|---|
| **Payven domain kodları** | `PV_BÜYÜK_HARF` | Payven iş kuralı + konnektör katmanı | `PV_INSUFFICIENT_FUNDS`, `PV_BANK_DECLINED`, `PV_3DS_FAILED`, `PV_CANNOT_REFUND` |
| **HTTP canonical kodlar** | `lowercase_snake_case` | Generic 4xx/5xx altyapı | `bad_request`, `unauthorized`, `validation_failed`, `rate_limit_exceeded` |
| **Provider (banka) kodları** | Bankaya göre değişir | İşlemi yürüten banka — ISO 8583 spec'i | `00` (başarı), `51` (yetersiz bakiye), `54` (süresi geçmiş kart) |

<Warning>
Ödeme/iş kuralı hatalarını `bank_declined` gibi snake_case değerlerle karşılaştırmayın — bu kodlar
**`PV_` önekli ve büyük harflidir** (`PV_BANK_DECLINED`). Tam liste:
[Payven Domain Kodları](/sanal-pos/errors/payven-codes).
</Warning>

Yanıttaki alan eşleşmesi:

| Yanıt alanı | Kategori |
|---|---|
| `code` (problem+json hata yanıtının body'sinde) | Payven domain veya HTTP canonical |
| `error_code` (failed ödeme sorgusunda data alanı olarak) | Payven domain |
| `provider_error_code` (failed ödeme sorgusunda data alanı olarak) | Banka — ISO 8583 |

## Hata yanıt formatı

Tüm hatalar — banka reddi dahil — [RFC 9457 problem+json](/documentation/concepts/errors) formatında uygun HTTP durum koduyla döner:

```json
{
  "type":          "https://docs.payven.com.tr/errors/PV_INSUFFICIENT_FUNDS",
  "title":         "Yetersiz bakiye",
  "status":        422,
  "code":          "PV_INSUFFICIENT_FUNDS",
  "detail":        "Banka kart bakiyesinin yetersiz olduğunu bildirdi (banka kodu: 51).",
  "instance":      "/api/v1/payments",
  "correlation_id": "9f1c8e76-2a3b-4f12-9c8d-12cb24a8a8a8"
}
```

Sonradan `GET /api/v1/payments/{id}` ile sorgulanan **failed** ödemenin yanıtı `200 OK` döner; banka detayları `error_code` ve `provider_error_code` data alanlarında taşınır — bkz. [Payment Objesi](/sanal-pos/payment-object).

## Konsoldaki canlı katalog

Sürekli güncellenen **konnektör hata kodu kataloğu** konsolda mevcuttur:

→ [Konsol → Konnektör Hata Kodları](https://dashboard.payven.com.tr/connector-error-codes)

Bu ekran her bankanın özel kod açıklamalarını, Payven domain kodu eşlemesini ve önerilen kullanıcı mesajlarını içerir.

## Hata yönetimi pratik kılavuz

| Durum | Yapılacak |
|---|---|
| `validation_failed`, `PV_INVALID_*` | İsteği düzeltip yeniden gönderin (retry yok) |
| `unauthorized` | Token alın / refresh edin |
| `forbidden` | İlgili organizasyon yöneticisi / Payven satış ile iletişime geçin |
| `rate_limit_exceeded` | `Retry-After` header'ına uyup backoff ile retry edin |
| `idempotency_key_in_use` | Aynı anahtarla farklı body göndermeyi durdurun veya farklı anahtar üretin |
| `PV_BANK_DECLINED`, `PV_DO_NOT_HONOR` | Müşteriye nazik mesaj gösterip başka kart önerin (`provider_error_code` daha spesifik bilgi) |
| `PV_TIMEOUT` | Smart Retry zaten devreye girer — istemci tarafında ek bir şey yapmayın |
| `PV_FRAUD_SUSPECTED` | Müşteriye genel "işlem onaylanmadı" mesajı gösterin (spesifik sebep paylaşmayın — fraud sinyalini sızdırır) |
| `5xx` (sunucu hatası) | Aynı `Idempotency-Key` ile exponential backoff retry |

Genel hata yönetimi prensibi ve retry kodu örnekleri: [Hata Yönetimi (Konsept)](/documentation/concepts/errors).
