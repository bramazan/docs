---
title: "Hakediş (Settlement) Kayıtları"
description: "Gün sonu hakediş kayıtları, devreden iade/iptal kalemleri ve orantılı komisyon iadesi."
---

Settlement, Payven'in her bayi için tuttuğu **gün sonu hakediş** kaydıdır. Dönem (Türkiye saatiyle bir tam gün) içindeki tahsilatlar, iadeler ve komisyonlar tek satırda özetlenir; bayinin hesabına geçecek net tutar bu kayıttan okunur.

## Endpoint'ler

```http
GET    /api/v1/settlements                    # Liste (sayfalı)
GET    /api/v1/settlements/{id}               # Tek settlement detayı
GET    /api/v1/settlements/{id}/carry-items   # Satıra devreden iade/iptal kalemleri
GET    /api/v1/settlements/stats              # Status bazlı özet sayaçlar (KPI)
GET    /api/v1/settlements/export             # CSV export
POST   /api/v1/settlements                    # Manuel settlement oluştur (operasyonel)
PUT    /api/v1/settlements/{id}/status        # Durum güncelle
POST   /api/v1/settlements/{id}/cancel        # Settlement iptali
POST   /api/v1/settlements/{id}/resubmit      # Failed settlement'ı yeniden kuyruğa al
POST   /api/v1/settlements/regenerate         # Dönemi yeniden üret (operasyonel)
```

Bearer access token gerektirir (OAuth 2.0 Client Credentials).

## Liste

Filtreler: `merchant_id`, `source_code` (banka kodu), `currency`, `status`, `start_date`, `end_date` (ISO 8601 + `+03:00` Türkiye offset'i — URL'de `%2B03%3A00` olarak encode edin).

```bash
curl "https://vpos.payven.com.tr/api/v1/settlements?page=1&page_size=20&start_date=2026-06-01T00%3A00%3A00%2B03%3A00&end_date=2026-06-11T23%3A59%3A59%2B03%3A00" \
  -H "Authorization: Bearer $PAYVEN_TOKEN"
```

Yanıt — sayfalı liste:

```json
{
  "items": [
    {
      "id":                            "8e3f5c12-...",
      "source_feature":                "sanalpos",
      "merchant_id":                   "3fa85f64-...",
      "merchant_name":                 "Örnek Ticaret A.Ş.",
      "period_start":                  "2026-06-10T00:00:00+03:00",
      "period_end":                    "2026-06-10T23:59:59.9999999+03:00",
      "source_code":                   "GARANTI",
      "currency":                      "TRY",
      "gross_amount":                  187435000,
      "refund_amount":                 2350000,
      "bank_commission":               6747260,
      "platform_commission":           1872500,
      "parent_commission_paid":        0,
      "net_amount":                    176465240,
      "marketplace_commission_income": 0,
      "sub_payout_obligations":        0,
      "real_net_earning":              176465240,
      "transaction_count":             1247,
      "refund_count":                  18,
      "status":                        "Settled",
      "settled_at":                    "2026-06-11T09:00:00.000+03:00",
      "bank_reference":                "STL-2026-06-10-789",
      "notes":                         null,
      "created":                       "2026-06-11T00:30:11.000+03:00"
    }
  ],
  "page":              1,
  "total_pages":       3,
  "total_count":       62,
  "has_previous_page": false,
  "has_next_page":     true
}
```

| Alan | Açıklama |
|---|---|
| `source_feature` | Kaydı üreten modül (`sanalpos`) |
| `source_code` | Banka/sağlayıcı kodu (örn. `GARANTI`, `HALKBANK`) |
| `period_start`, `period_end` | Dönem sınırları — Türkiye saatiyle tam gün (ISO 8601 + `+03:00`) |
| `gross_amount` | Brüt tahsilat (kuruş) |
| `refund_amount` | Dönem içi iadeler **+ devreden iade/iptal kalemleri** toplamı |
| `bank_commission` | Banka komisyonu — elde tutulan kısma orantılı (aşağıya bakın) |
| `platform_commission` | Payven platform komisyonu — elde tutulan kısma orantılı |
| `parent_commission_paid` | Alt-bayinin üst bayiye ödediği split komisyonu (marketplace dışında 0) |
| `net_amount` | `gross - refund - bank_commission - platform_commission - parent_commission_paid` |
| `marketplace_commission_income` | Marketplace parent'ın alt-bayilerden komisyon geliri (gross'a dahildir, bilgi amaçlı ayrıca gösterilir) |
| `sub_payout_obligations` | Marketplace parent'ın alt-bayilere ödeme yükümlülüğü |
| `real_net_earning` | Gerçek hakediş = `net_amount - sub_payout_obligations` |
| `transaction_count`, `refund_count` | Dönemdeki işlem ve iade adedi (devreden kalemler `refund_count`'a dahil) |
| `settled_at` | Bankanın transferi yaptığı an (status `Settled` olunca dolar) |
| `bank_reference` | Bankanın referans numarası |
| `status` | `Pending`, `Processing`, `Settled`, `Failed`, `Cancelled` |

<Note>
Settlement `status` alanı işlem (transaction) durumlarından farklı olarak **PascalCase** string taşır
(`"Pending"`, `"Settled"`, ...). Liste filtresinde `status` parametresi toleranslıdır.
</Note>

## Orantılı komisyon iadesi

Komisyonlar **elde tutulan tutara orantılı** hesaplanır: bir işlem kısmen iade edildiğinde o işlemin
platform ve banka komisyonu yalnızca iade edilmeyen (retained) kısım üzerinden settlement'a yansır;
iade edilen paya düşen komisyon size geri verilir. Tam iadede işlemin komisyonu tamamen sıfırlanır.

## Devreden kalemler (carry-forward)

Hesaplanmış bir hakediş satırı **asla geriye dönük değiştirilmez**. Dönemin satırı üretildikten
sonra gelen bir iade/iptal, **devreden kalem** olarak yazılır ve bir **sonraki** hakediş hesabında
tüketilir: kesinti yeni satırın `refund_amount`'una eklenir, iade edilen paya düşen orantılı
komisyon geri verimi `platform_commission` ve `bank_commission`'dan düşülür.

Bir satıra hangi kesintilerin devrettiğini detayda görebilirsiniz:

```bash
curl https://vpos.payven.com.tr/api/v1/settlements/8e3f5c12.../carry-items \
  -H "Authorization: Bearer $PAYVEN_TOKEN"
```

```json
[
  {
    "id":                  "c1a2b3d4-...",
    "kind":                "refund",
    "amount":              150000,
    "currency":            "TRY",
    "source_code":         "GARANTI",
    "transaction_id":      "7d2e9f01-...",
    "transaction_created": "2026-06-09T14:22:05.000+03:00",
    "occurred_at":         "2026-06-10T11:05:42.000+03:00"
  }
]
```

| Alan | Açıklama |
|---|---|
| `kind` | `refund` (iade) veya `void` (iptal) |
| `amount` | Kesinti tutarı (kuruş, pozitif) — satırın `refund_amount`'una eklendi |
| `transaction_created` | Orijinal işlemin tarihi (hangi dönemin işlemiydi) |
| `occurred_at` | İade/iptalin gerçekleştiği an |

## Özet sayaçlar (stats)

Liste filtresiyle aynı parametreleri alır; sayfalama yok, filtreye uyan **tüm** kayıtların
status dağılımını döner:

```json
{
  "total":            62,
  "total_net_amount": 1083921400,
  "pending":          3,
  "processing":       1,
  "settled":          56,
  "failed":           1,
  "cancelled":        1
}
```

## Status değişikliği

Bir settlement durumunu güncellemek için:

```bash
curl -X PUT https://vpos.payven.com.tr/api/v1/settlements/8e3f5c12.../status \
  -H "Authorization: Bearer $PAYVEN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "Failed",
    "notes":  "Tutar bankadan eksik geldi — destek talebi açıldı"
  }'
```

Status geçişleri webhook yayınlar (`sanalpos.settlement.processing` / `.completed` / `.failed`) —
bkz. [Webhook Olay Kataloğu](/sanal-pos/webhooks/events#settlement-olaylari).

`POST /settlements/{id}/cancel` settlement'ı iptal eder (`sanalpos.settlement.cancelled`),
`POST /settlements/{id}/resubmit` `Failed` durumdaki kaydı yeniden kuyruğa alır (geçersiz durumda
`409` döner).

## Manuel settlement oluşturma

Banka API entegrasyonu olmayan konnektörler için manuel settlement girişi:

```bash
curl -X POST https://vpos.payven.com.tr/api/v1/settlements \
  -H "Authorization: Bearer $PAYVEN_TOKEN" \
  -H "Idempotency-Key: stl-garanti-2026-06-10" \
  -H "Content-Type: application/json" \
  -d '{
    "merchant_id":         "3fa85f64-...",
    "period_start":        "2026-06-10T00:00:00+03:00",
    "period_end":          "2026-06-10T23:59:59+03:00",
    "source_code":         "GARANTI",
    "currency":            "TRY",
    "gross_amount":        187435000,
    "refund_amount":       2350000,
    "bank_commission":     6747260,
    "platform_commission": 1872500,
    "transaction_count":   1247,
    "refund_count":        18,
    "bank_reference":      "STL-2026-06-10-789"
  }'
```

## Parçalı hakediş ile ilişki

Gün sonu settlement'a ek olarak, bayi bazında N-saatlik pencerelerle üretilen
[Parçalı Hakediş](/sanal-pos/reporting/split-settlements) kayıtları ayrı bir kaynak olarak sunulur.
İki zincir bağımsızdır; devreden kalemler her zincirde kendi akışını izler.

## Mutabakat ile ilişki

Bir settlement, mutabakat tamamlandıktan sonra ilgili işlemlerin `settlement_date` alanına yazılır.
Detaylı akış: [Mutabakat Yaşam Döngüsü](/sanal-pos/reconciliation/lifecycle).
